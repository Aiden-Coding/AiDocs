Java 后端数据库基础

本文补齐 Java 应用开发所需的关系型数据库通用基础，帮助读者从 SQL 和事务走到 JDBC 与 MyBatis。SQL 方言和优化器行为会随数据库产品及版本变化，实际排查应以目标数据库文档和执行计划为准。

1. SQL 与关系建模​

关系型数据库用表、行和列组织数据。设计表时为实体选择稳定主键，明确字段类型、空值语义、唯一性和外键等约束。规范化有助于避免更新异常；为读性能进行反规范化时，需要明确冗余数据的同步策略。

SQL 常见操作包括查询（SELECT）、新增（INSERT）、更新（UPDATE）和删除（DELETE）。写操作必须带有明确条件，并在执行前确认影响范围。查询应只读取需要的列，分页排序应使用稳定、唯一的排序键，避免翻页期间结果重复或遗漏。

应用层应使用参数化查询。不要把用户输入拼接进 SQL 文本；参数化可避免输入被解释为 SQL 语法，也有利于语句复用。

2. 索引与查询计划​

索引帮助数据库定位数据，会占用存储空间并增加写入维护成本。设计索引时，应结合过滤条件、排序、关联键、选择性和写入负载，避免给每一列都建索引。

复合索引通常按最左前缀匹配规则利用前导列；列顺序需要结合实际查询条件设计。对索引列施加函数、发生隐式类型转换或使用不匹配的字符集与排序规则，可能阻碍索引有效使用，具体取决于数据库优化器。

使用目标数据库的 EXPLAIN 或等价工具检查执行计划，重点关注访问方式、候选索引、预估行数、过滤条件、排序和临时结构。执行计划是优化器的估算；发现慢查询后还需结合真实耗时、数据分布和运行时统计验证。

3. 事务与并发控制​

事务将一组读写作为一个逻辑单元提交或回滚。ACID 常用于描述事务的原子性、一致性、隔离性和持久性。应用需要明确事务边界，避免把远程调用、长时间计算或用户交互放在数据库事务内。

常见隔离级别包括读未提交、读已提交、可重复读和可串行化。不同数据库对快照、锁和幻读的实现存在差异，不能只凭隔离级别名称推断所有并发行为。并发更新时应设计冲突处理策略，例如原子条件更新、乐观版本号或显式锁定。

事务失败时要决定重试范围，并确保重试操作具备幂等性。死锁通常要求数据库回滚其中一个事务；应用应记录诊断信息，并只对可安全重试的事务做有限重试。

4. JDBC 基本链路​

JDBC 提供 Java 程序访问关系型数据库的标准 API。典型流程是从 DataSource 获取 Connection，创建 PreparedStatement，绑定参数，执行查询或更新，读取 ResultSet，最后释放资源。

String sql = "SELECT id, name FROM customer WHERE id = ?";
try (Connection connection = dataSource.getConnection();
     PreparedStatement statement = connection.prepareStatement(sql)) {
    statement.setLong(1, customerId);
    try (ResultSet resultSet = statement.executeQuery()) {
        if (resultSet.next()) {
            return new Customer(resultSet.getLong("id"),
                    resultSet.getString("name"));
        }
    }
}

PreparedStatement 的占位参数用于传值，不能替代动态表名、列名或排序关键字的白名单校验。连接、语句和结果集都应及时关闭；使用连接池时关闭逻辑连接通常代表归还连接，而不是销毁物理连接。

事务默认通常为自动提交。需要多条语句原子执行时，关闭自动提交，在成功时提交、失败时回滚，并确保最终恢复连接状态。框架管理事务时，不要在业务代码中擅自提交或关闭框架持有的连接。

5. 从 JDBC 衔接到持久层框架​

MyBatis 在 JDBC 之上管理 SQL 映射、参数处理、结果映射和插件扩展；连接池管理连接复用。理解连接生命周期、事务边界和参数绑定，能帮助定位 Mapper 查询错误、连接泄漏和事务行为问题。

6. 排查慢 SQL 的基本步骤​

  1. 获取实际 SQL、参数、数据库版本和真实耗时，确认问题发生频率及影响范围。
  2. 使用执行计划检查扫描范围、索引选择、行数估算、排序和关联方式。
  3. 检查谓词、类型、索引列顺序、返回列和分页方式，提出可验证的修改。
  4. 在接近真实数据量的环境比较执行计划与耗时，并观察写入成本及资源占用。
  5. 上线后监控延迟、错误率和数据库负载，保留回退方案。

学习检查​

  • 能写出参数化查询，并说明 JDBC 资源如何关闭。
  • 能解释事务边界、隔离级别及并发更新冲突的处理方式。
  • 能阅读执行计划并提出基于数据验证的索引或 SQL 改进。
  • 能说明 MyBatis、JDBC 连接和连接池之间的职责关系。
